# Design Output Schema

A design session should not be a single architecture note. It should include intake, options, review gates, and handoff artifacts.

Required or recommended files:

```text
00A_CONTEXT_USED_FOR_DESIGN.md
00_DESIGN_INTAKE.md
01_QUESTIONS_TO_USER.md
02_REQUIREMENT_TRACEABILITY.md
02A_NON_GOALS.md
03_DESIGN_OPTIONS.md
03A_OPTION_SCORE_MATRIX.md
04_RECOMMENDED_ARCHITECTURE.md
05_INTERFACE_DRAFT.md
06_LAUNCH_CONFIG_DRAFT.md
07_RISK_AND_ASSUMPTIONS.md
08A_ACCEPTANCE_TESTS.md
08_DESIGN_REVIEW.md
09_REQUIREMENT_COVERAGE_MATRIX.md
10_INTERFACE_CONFIG_CONNECTIVITY_CHECK.md
11_IMPLEMENTATION_HANDOFF_PROMPT.md
12_DESIGN_STATE.md
13_ADR_CANDIDATES.md
PARALLEL_LANE_SUMMARY.md
CONFLICTS_AND_DEPENDENCIES.md
MERGED_DECISION.md
SESSION_INDEX.md
SESSION_META.json
```

Questions have no hard limit. They must be grouped as P0/P1/P2 and should be asked in rounds when many questions exist.

If subagents are used in parallel, the session must include lane summary, conflicts/dependencies, and merged decision.
